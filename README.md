# Система управління послугами хімчистки

Навчальна практика з розробки та тестування програмного забезпечення.

- **Варіант:** 12
- **Рівень складності:** I (високий, 10–12 балів)
- **Виконав:** Турчак Богдан Богданович, група ІС 23-01

## Тема

Система управління послугами хімчистки: приймання речей, вибір послуг, розрахунок вартості, контроль готовності замовлень.

## Мета

Розробити консольний застосунок мовою Python, який автоматизує облік роботи хімчистки: від приймання речей у клієнта до видачі готового замовлення. Під час розробки пройти повний цикл створення програмного забезпечення: аналіз вимог, UML-проєктування, реалізацію з використанням ООП, патерна проєктування та бази даних SQLite, тестування й документування.

## Призначення

Програма призначена для працівників хімчистки (приймальника та адміністратора). Вона замінює паперові квитанції та журнал замовлень і дозволяє:

- зберігати дані про клієнтів, послуги та замовлення в одному місці;
- автоматично й без помилок розраховувати вартість і строк виконання;
- у будь-який момент бачити, на якому етапі перебуває кожне замовлення;
- швидко знаходити замовлення клієнта під час видачі.

## Заплановані функції

1. **Облік клієнтів.** Реєстрація, перегляд, редагування та видалення клієнтів (ПІБ, телефон). Клієнта з незакритими замовленнями видалити не можна.
2. **Ведення прайс-листа послуг.** Додавання, перегляд і редагування послуг (назва, ціна, тривалість виконання), деактивація послуг, які більше не надаються.
3. **Приймання речей (оформлення замовлення).** Створення замовлення для клієнта й додавання речей із типом виробу, матеріалом, кольором і описом дефектів.
4. **Вибір послуг для речей.** Для кожної речі вибирається одна або кілька активних послуг із прайс-листа.
5. **Розрахунок вартості замовлення.** Вартість залежить від послуг, коефіцієнта матеріалу, терміновості та знижки постійного клієнта.
6. **Розрахунок дати готовності.** Строк визначається за найдовшою послугою, а для термінового замовлення скорочується.
7. **Контроль статусів замовлення.** Прийнято → В роботі → Готово → Видано, а також Скасовано. Недопустимі переходи система блокує.
8. **Видача замовлення клієнту.** Видати можна лише готове замовлення. Під час видачі фіксується дата, а замовлення закривається.
9. **Пошук, фільтрація та сортування.** Пошук клієнта за телефоном або ПІБ, замовлення за номером; фільтрація замовлень за статусом і клієнтом; сортування за датою, вартістю чи датою готовності; перелік прострочених замовлень.
10. **Постійне зберігання даних.** Усі дані зберігаються в SQLite і доступні після повторного запуску програми.

## Сутності предметної області

| Сутність | Клас | Опис |
|---|---|---|
| Клієнт | `Client` | Особа, яка здає речі в хімчистку |
| Послуга | `Service` | Позиція прайс-листа (хімчистка, прання, прасування, виведення плям…) |
| Замовлення | `Order` | Квитанція: речі, які клієнт здав за один візит |
| Річ | `OrderItem` | Окремий виріб у замовленні з вибраними послугами |

## Дані для зберігання в базі даних (SQLite)

| Таблиця | Дані | Зв'язки |
|---|---|---|
| `clients` | id, ПІБ, телефон (унікальний), дата реєстрації | — |
| `services` | id, назва, базова ціна, тривалість (днів), ознака активності | — |
| `orders` | id (номер квитанції), id клієнта, дата приймання, планована дата готовності, терміновість, статус, загальна вартість, дата видачі | `client_id` → `clients.id` |
| `order_items` | id, id замовлення, тип виробу, матеріал, колір, дефекти, вартість речі | `order_id` → `orders.id` |
| `order_item_services` | id речі, id послуги, ціна послуги на момент оформлення | `item_id` → `order_items.id`, `service_id` → `services.id` |

Детальну структуру бази даних (типи полів, ключі, ER-діаграму) буде розроблено на етапі проєктування.
